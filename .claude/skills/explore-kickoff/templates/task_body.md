# _explore Task Body 标准模板

新任务起草时复制下面模板，按 7 问回答填充。

```
- [ ] **#XXX <一句话标题：动作 + 对象 + 关键约束>** — <一句话目标，扩展标题的具体性>

  **核心 vs 增强标记**：[核心层 / 增强层 / 中间梳理]

  **方向**：
  - <切入点 1：具体问题 + 期望深度>
  - <切入点 2>
  - <切入点 3>
  - <切入点 4>
  - <切入点 5>
  - <切入点 6>

  **相关锚点**：[[设计文档 1]]、[[设计文档 2]]、项目代码 `scripts/...` / `test/...`、外部参考 URL

  **期望产出**：
  1. <产出 1：明确产出形态，如"对照表" / "代码骨架" / "判决"等>
  2. <产出 2>
  3. <产出 3>
  4. <产出 4：可选>

  **边界**：仍不做美术资产；不替换 Godot 主框架；不修改主项目 `scripts/`、`assets/`（agent 仅读不写）；<其他特定边界>
```

## 撰写规则

1. **方向不超过 6 条**：超过则拆分 task，避免重蹈 #005 超时（5 阶段 6 项产出导致 STEP-2 超时）
2. **期望产出不超过 4 项**：同上
3. **核心 vs 增强标记必填**：监督者在阶段 4 决策时依赖这个标记
4. **相关锚点要含项目代码路径**：让 agent 在 STEP-1 定调时能读到本地实证（避免凭推断猜测）
5. **边界要写具体**：模糊的"不做太多"对 agent 没约束力；要写明"不修改 X / 不评估 Y / 不写 Z"

## 综合 / 收口轮的特殊模板

最后一轮"综合落地"或"收口"任务的产出**应大幅缩减**（避免 #005 超时教训）：

```
- [ ] **#XXX <主题>方向最终综合**

  **核心 vs 增强标记**：[中间梳理]

  **本次特殊定位**：综合 #001-#00N 全部结论，**不做新调研**，仅汇总。

  **方向**：
  - 综合前 N 轮判决（每轮一段，~50 字）
  - 给出推荐主路径 + 关键放弃理由

  **相关锚点**：[[log/<UTC>/<前 N 轮报告>]]

  **期望产出**（**严格 ≤ 3 项**）：
  1. 收敛判决（一段，~200 字）
  2. 推荐主路径（一段，~150 字）
  3. 衍生子问题（≥3 条）

  **边界**：不写代码；不做新 WebSearch；不超过 STEP-3 的产出深度
```

把"完整 roadmap / 视觉案例库 / 文件清单 / 风险清单 / 决策推荐表 / 用户下一步动作"等扩展产出**留给监督者在主对话中接力综合**或后续 MVP 设计文档承担——**不要塞进单轮 _explore task**。
